# Wabi 구현 계획서

## 0. 출처와 범위

- **원본**: `Docs/Design/WabiDesignSystem.dc.html` (Claude Design 프로젝트 `cc00ea2b-15f8-4984-a1f1-3739f99ec91b`에서 내려받은 사본)
- **디자인 명세**(색상·타이포·간격·컴포넌트·화면 구성·모션)는 원본 캔버스가 확정된 사실이므로 그대로 따릅니다. 임의로 바꾸지 않습니다.
- **제품 콘텐츠**(비자·세금·보험·계약 등 현실 정보)는 캔버스에 적혀 있더라도 확정된 사실이 아니라 화면을 채우기 위한 예시입니다. 직접 조사해 확인한 값으로 교체한 뒤에만 코드에 넣습니다. 조사는 Research-team에 의뢰했습니다.
- 원본은 디자인 시스템(01~04 섹션)과 **동작하는 프로토타입**(05 섹션)을 함께 담고 있습니다. 두 가지를 모두 구현합니다.

## 1. 제품 정의

워킹홀리데이를 준비하는 사람과 현지에 도착한 사람을 위한 모바일 우선 앱입니다. 할 일은 많지만 한 번에 알아야 할 것은 언제나 하나뿐이라는 전제로 설계되었습니다.

- 대상: 출국 전 준비 단계, 현지 정착 단계
- 첫 화면은 D-day
- 다국가 지원 (호주 / 캐나다 / 일본)
- 존댓말, 간결한 카피

## 2. 설계 원칙 (구현 시 반드시 지킬 것)

1. **한 화면에 블록 3~4개**. 그 이상 필요하면 다음 화면으로 넘깁니다. 목록은 3줄까지 보여주고 나머지는 '전체 보기'로 감춥니다.
2. **시선 순서를 고정합니다**. 위에서 아래로 상태 → 다음 행동 → 목록 → 탭바. 화면이 바뀌어도 이 순서는 바뀌지 않습니다.
3. **색이 아니라 크기로 강조합니다**. 팔레트는 무채색 하나뿐이고, 중요도는 타이포 크기·여백·잉크 대비로만 표현합니다. 유채색은 마감 임박 한 곳에만 쓰는 `alert` 하나로 제한합니다.

## 6. 데이터

데이터는 화면 코드와 분리해 `src/Front/common/data`(또는 Architecture가 정한 위치)에 둡니다.

### 6.1 구조 (캔버스에서 확정)

| 상수 | 구조 |
|---|---|
| `COUNTRIES` | 국가 코드별 `label / depart / visa` |
| `TASKS` | `id / phase(pre·post) / title / meta / week / urgent / tag / body / items / done` |
| `GUIDE` | 상황(`pre`·`post`)별 문항 배열, 각 문항은 `title / body / points` |
| `PAIN` | `num / when / title / body / points` |

분량 기준: `TASKS` 9건(pre 4 · post 5), `GUIDE` 상황별 5문항, `PAIN` 6건.

### 6.2 값 (조사 후 확정)

캔버스에 들어 있는 값 — 비자 심사 3주, 세금 번호가 없을 때 최고 세율, 계좌 개설 도착 후 3일 내, 보험 증서 요구 여부, 국가별 출국일과 비자 만료일 등 — 은 **확인되지 않은 예시**입니다. 다음 순서로 처리합니다.

1. Research-team에 국가별(호주·캐나다·일본) 실무 정보를 공식 출처 기준으로 의뢰합니다. 산출물은 `/home/fefdfea/FF/Organize/Research-team/Research-team/Result/Data/` 아래 JSON입니다.
2. 조사 결과가 도착하면 그 값으로 `TASKS` · `GUIDE` · `PAIN`을 다시 씁니다. 각 항목에는 출처 URL을 함께 보관합니다.
3. 조사로 확인되지 않은 항목은 임의로 채우지 않고 화면에서 뺍니다.
4. Front-end는 조사 결과가 오기 전까지 데이터 구조와 화면만 구현하고, 값은 조사 산출물로 주입받는 형태로 설계합니다.

`COUNTRIES`는 국가별로 다른 실제 요건을 담게 되므로, 세 국가가 같은 할 일 목록을 공유하던 캔버스 구조를 국가별 할 일 목록으로 확장해야 합니다.

## 7. 동작 명세

- 탭 이동 시 열려 있던 상세는 닫습니다.
- 체크 토글은 행 전체가 아니라 체크 원에서만 발생하며, 행 클릭은 상세를 엽니다 (이벤트 전파 차단).
- 완료 항목: 제목 `muted` + 취소선, 메타는 '완료'로 바뀝니다.
- 긴급 항목(`urgent`이고 미완료): 체크 테두리와 메타 글자가 `alert`.
- NEXT 카드는 미완료 항목 중 첫 번째를 보여주고, 설명은 본문의 첫 문장만 씁니다.
- 진행률은 기본 할 일 + 직접 추가한 할 일을 합쳐 계산합니다.
- 직접 추가한 할 일은 마감이 '오늘까지' 또는 '이번 주'이면 홈의 '이번 주 할 일'에 함께 나옵니다.
- 테마와 국가는 '나' 탭 설정에서 바꿀 수 있습니다.

## 8. 카피 규칙

1. 존댓말, 한 문장. 감탄사와 느낌표는 쓰지 않습니다.
2. 행동 버튼은 동사로 끝냅니다. "지금 하기", "가입하기", "예약하기".
3. 마감은 상대 표현으로. "오늘까지", "도착 후 3일 내".
4. 숫자는 단위와 붙여 씁니다. "8 / 14", "D-12".

## 10. 출국일 입력 (사용자 승인 2026-08-28)

D-day와 비자 만료일은 조사로 확인할 수 있는 사실이 아니라 이용자마다 다른 개인 값입니다. 캔버스가 `COUNTRIES`에 하드코딩해 둔 출국일과 비자 만료일은 쓰지 않고, 다음과 같이 입력받아 산출합니다.

### 10.1 입력 위치

'나' 화면의 설정 목록에 **출국일** 항목을 추가합니다. 기존 3개(화면 모드 · 알림 · 국가 변경)와 같은 60px 행 형식을 따르고, 값이 없으면 우측에 '입력하기'를, 있으면 선택한 날짜를 보여줍니다.

날짜 선택은 브라우저 기본 `input[type=date]`를 씁니다. 외부 의존성이 없고 모바일에서 OS 기본 날짜 선택기가 뜨며 키보드 접근성이 확보됩니다.

### 10.2 산출 규칙

- **D-day** = 출국일 − 오늘. 출국 당일은 `D-DAY`, 지난 뒤에는 `D+n`으로 표시합니다.
- **비자 만료일** = 출국일 + 국가별 체류 허용 기간(조사로 확인된 값). 해당 국가의 체류 허용 기간이 조사로 확인되지 않았다면 비자 만료일 줄을 표시하지 않습니다.
- **출국일이 입력되지 않았으면 홈의 D-day 자리에 `D-0`을 기본으로 보여줍니다** (사용자 지시 2026-08-28). 이전에는 "'나' 화면에서 출국일을 입력하면 D-day가 표시됩니다"라는 빈 상태 문구를 두었으나, 첫 화면이 비어 보이지 않도록 기본값을 표시하는 쪽으로 바꿉니다.
  - `D-0`은 **출국일이 없는 상태**의 표시이고, 출국일을 입력한 뒤 출국 당일이 되면 `D-DAY`가 나옵니다. 두 표기가 다르므로 섞지 마세요.
- 반면 '나' 화면의 출국일·비자 만료일 줄은 **그대로 빈 상태로 둡니다.** 여기는 실제 값을 보여주는 자리라 임의의 기본값을 넣으면 거짓이 됩니다. D-day 자리만 예외입니다.

### 10.3 구현 시 주의

- **오늘 날짜는 반드시 클라이언트에서 계산합니다.** 이 라우트는 정적 프리렌더 대상이므로 서버 렌더 시점에 `new Date()`를 쓰면 빌드 시점 날짜로 고정되고, 하이드레이션 불일치도 발생합니다.
- 출국일은 `localStorage`에 저장합니다. 저장 범위 경계는 Security 검토서 2절을 따릅니다.

| `744 ~ 1179px` 태블릿 | 아이콘 레일 + 본문 620px 중앙 |
| `≥ 1180px` 데스크톱 | 사이드바 + 본문 + 우측 요약. **레이아웃 최대 폭 1440** |

**최대 폭은 1440입니다** (사용자 지시 2026-08-28. 처음 1280으로 정했다가 넓혔습니다). 1180 이상에서 데스크톱 레이아웃으로 전환하되, 앱 전체 폭은 **1440에서 멈추고 그보다 넓은 창에서는 가운데 정렬**합니다.

폭이 늘어나도 **좌우 패널과 본문 콘텐츠는 고정입니다.**

| 요소 | 폭 |
|---|---|
| 좌측 사이드바 | 236 고정 |
| 우측 요약 패널 | 336 고정 |
| 본문 **콘텐츠** | 620 상한 유지 |
| 본문 **컨테이너** | 남는 폭을 가져가고, 그 안에서 콘텐츠 620을 가운데 정렬 |

1440에서는 본문 컨테이너가 868이 되는데, 콘텐츠까지 868로 늘리면 확장 규칙 "본문 폭은 620px에서 멈춥니다"를 어깁니다. **남는 폭은 여백으로 둡니다.** 이 구분은 QA가 이미 한 번 오판할 뻔한 지점이라(TPC-26) 컨테이너와 콘텐츠를 나눠 재야 합니다.

### 11.2 확장 규칙 (캔버스 원문)

- **본문 폭은 620px에서 멈춥니다.** 넓어진 화면에서 글줄이 길어지지 않게 합니다.
  - 데스크톱에서 이 값을 확인할 때는 **컨테이너가 아니라 그 안의 실제 콘텐츠를 재야 합니다.** 홈·메모의 본문 컨테이너는 `flex: 1`이라 708px이고, 좌우 패딩 44px씩을 뺀 콘텐츠가 620px입니다. 컨테이너를 재면 620 초과로 오판합니다.
- **정보를 추가하지 않습니다.** 데스크톱 우측 요약은 다른 화면에 이미 있는 내용을 옮겨 놓은 것뿐입니다.
- **타이포만 한 단계 키웁니다.** D-day 60 → 88, 제목 24 → 30, 본문 15는 그대로 둡니다.
  - 두 값의 **적용 구간이 다릅니다**(QA가 캔버스 목업 대조로 확인). D-day는 모바일 60 · 태블릿 72 · 데스크톱 88로 **3단계**이고, 제목은 모바일 24 · **태블릿부터 30**으로 2단계입니다. 제목을 데스크톱에서만 키우면 태블릿이 캔버스와 어긋납니다.
- **터치와 커서를 함께 지원합니다.** 태블릿의 탭 대상은 모바일과 같은 최소 48px를 유지하고, hover 상태는 데스크톱에서만 씁니다.

> 한 줄 요약(캔버스): 모바일은 순서로, 데스크톱은 배치로 같은 우선순위를 만듭니다. 화면이 커져도 사용자가 먼저 보는 것은 언제나 D-day와 NEXT 하나입니다.

화면마다 다릅니다. **새 정보를 만들지 않고 다른 화면의 내용을 옮겨 놓습니다.**

| 할 일 | 캔버스에 데스크톱 목업이 없습니다. 아래 11.6절 참고 |

### 11.6 캔버스에 목업이 없는 화면

데스크톱 `할 일`은 캔버스에 목업이 없습니다. **임의로 만들지 말고** 다음 원칙으로만 처리합니다.

## 13. 출처 표시 (사용자 지시 2026-08-28)

데이터의 `sourceUrl`을 화면에 노출합니다. 비자·세금·보험처럼 틀리면 이용자가 실제로 손해를 보는 정보이므로, 이용자가 원문을 직접 확인할 수 있어야 합니다.

### 13.1 노출 위치

정보 예산을 지키기 위해 **목록에는 넣지 않고 상세에서만** 보여줍니다.

| 위치 | 표시 지점 |
|---|---|
| 할 일 상세 화면 | 준비물 목록 아래 |
| 가이드 답변 | 대처법 목록 아래 |
| 어려움 답변 | 대처법 목록 아래 |
| '나' 화면 국가 정보 카드 | 비자 만료일 줄 아래 |

홈·할 일·문서 화면의 목록 행에는 넣지 않습니다. "한 화면에 블록 3~4개" 원칙과 64px 행 높이가 무너집니다.

### 13.2 형식

- caption 규격을 따릅니다. JetBrains Mono 11px, 색은 `muted`.
- 링크 문구는 `출처`만 쓰지 않고 **도메인을 함께 보여줍니다**. 화면에서도 어디서 온 정보인지 알 수 있고, 스크린리더로 링크만 훑을 때도 구분됩니다. 예: `출처 immi.homeaffairs.gov.au`
- 외부로 나가는 링크이므로 `target="_blank"`와 `rel="noopener noreferrer"`를 함께 붙입니다.
- 새 탭으로 열린다는 사실을 스크린리더에 알리기 위해 `aria-label`에 이를 포함합니다.
- 새 색상 토큰을 만들지 않습니다. `muted`를 그대로 쓰고 호버 시 `text`로 올립니다.

### 13.3 값이 없을 때

`sourceUrl`은 선택 필드입니다. 값이 없으면 **줄 자체를 렌더하지 않습니다.** 빈 링크나 '출처 없음' 같은 문구를 넣지 않습니다. 현재 `jp-move-in` 한 건이 여기에 해당합니다. 사실은 조사로 확인됐지만 원문 URL이 기록되지 않은 경우입니다.

## 14. 이용자 파일 저장 (폐기 — 16절로 대체)

> **폐기됨 (2026-08-28)** — 파일 저장 기능 자체를 만들지 않기로 했습니다. 사유와 대체안은 16절을 보십시오.
> 아래 원칙은 나중에 파일 저장을 다시 논의할 때를 위해 남겨 둡니다.

이용자가 추가한 파일을 저장하게 된다면 **IndexedDB에 `Blob`으로** 저장하고 `localStorage`에는 넣지 않습니다. `localStorage`는 문자열만 담을 수 있어 base64로 부풀려야 하고 용량 한도가 5MB 안팎이며 동기 API라 큰 값을 다루는 동안 화면이 멈춥니다.

`localStorage`는 테마·국가·출국일·메모처럼 짧은 값에만 씁니다. 현재 저장 중인 값이 전부 여기에 해당합니다.

## 16. 문서 탭을 메모 탭으로 (사용자 지시 2026-08-28)

**이용자 파일 저장 기능은 만들지 않습니다.** 앞서 이 절에 있던 IndexedDB 저장·AES-GCM 암호화·파일별 키·60일 보관·매직 넘버 검사 명세는 전부 폐기합니다.

### 16.1 폐기 이유

파일 저장은 이 앱의 크기에 비해 딸려 오는 것이 너무 많았습니다. 암호화, 키 파쇄, 보관 기간 약속과 실제 삭제, 위장 파일 검사, 미리보기 샌드박스까지 붙었고 그중 어느 하나만 빠져도 이용자에게 한 약속이 깨지는 구조였습니다.

이용자 로컬 파일 경로를 참조하는 방식(File System Access API의 `showOpenFilePicker`)도 검토했으나 **Safari가 데스크톱·iOS 모두 미지원, Firefox 미지원, 표준 상태도 experimental**입니다(MDN browser-compat-data 직접 확인). 모바일 우선인 이 앱에서 iOS 이용자가 기능을 아예 못 쓰게 되므로 채택할 수 없습니다.

서류 정보 자체는 이미 할 일 상세의 "준비물"이 전달하고 있어 정보 전달 목적에는 구멍이 없습니다.

### 16.2 대신 넣는 것: 메모

문서 탭 자리에 **이용자가 직접 적는 메모**를 둡니다. 남이 만든 파일을 보관하는 것이 아니라 이용자가 스스로 적어 두는 것이라, 앞의 무거운 장치들이 필요 없습니다.

- 탭 라벨을 `문서`에서 `메모`로 바꿉니다. `TabBar`의 아이콘과 위치, 4탭 구성은 그대로입니다.
- 메모 한 편은 **제목과 본문**입니다. 캔버스 데스크톱 메모 목업이 제목 입력과 내용 입력을 나눠 두고 있고, 목록도 제목 + 부제(내용 요약) + 날짜로 그립니다. (이전 명세는 본문 하나였으나 캔버스 확인 후 정정)
- 저장은 `localStorage`입니다. 테마·출국일·직접 추가한 할 일과 같은 자리에 둡니다. 짧은 텍스트라 IndexedDB가 필요 없습니다.
- 레코드: `{ id, title, body, updatedAt }`.

### 16.3 화면

- **목록**: 제목 + 내용 한 줄 요약 + 날짜입니다. 최근 수정 순으로 정렬합니다.
- **추가·편집**: `BottomSheet` 안에서 합니다. 여러 줄을 입력해야 하므로 **`TextArea` 컴포넌트를 `common/component`에 새로 만듭니다.** `TextField`의 규격(radius 14, `sunken` 배경, 1.5px `line` 테두리, 15px)을 그대로 따르되 높이만 늘리고 세로 리사이즈를 막습니다.
- **삭제**: 목록 행에서 삭제할 수 있게 하고 확인을 한 번 받습니다.
- **빈 상태**: `아직 적어 둔 메모가 없습니다.`

### 16.4 카피

파일 저장 시절의 문구는 전부 걷어냅니다. "기기에만 저장", "60일 후 자동 삭제", "만료일 알림" 같은 표현이 남아 있으면 안 됩니다.

- 화면 안내 한 줄: `기억해 둘 것을 적어 두세요. 이 기기에만 저장됩니다.`
- **추가·편집 시트 안내 한 줄** (`SecurityReview.md` 9절 권고): `계좌번호나 여권번호처럼 민감한 정보는 적지 않기를 권합니다.`

메모는 평문으로 저장합니다. 로그인도 앱 잠금도 없는 구조에서는 암호화를 넣어도 실질적인 보호가 되지 않기 때문입니다(파일 저장에서 확인한 것과 같은 이유). 이용자가 무엇을 적을지 통제할 수 없으므로 막는 대신 알려주는 쪽을 택합니다. 앱 잠금 기능이 생기면 그때 재검토합니다.

`localStorage`도 브라우저 저장공간을 지우면 사라지므로 영구 보존을 암시하지 않습니다. 다만 이용자가 직접 적은 짧은 글이라 파일 때처럼 강한 경고는 두지 않습니다.

## 17. `SourceLink` 스킴 검사 (`SecurityReview.md` 9절)

`SourceLink`가 URL 스킴을 검사하지 않아 `https` 전용 규칙이 데이터 규율에만 의존하고 있습니다. 조사 결과에 `http` URL이 섞이면 그대로 렌더됩니다.

`new URL(url).protocol`이 `"https:"`가 아니면 **아무것도 렌더하지 않습니다.** 파싱 실패 시 `null`을 반환하는 기존 처리와 같은 방식입니다. 데이터에 잘못된 값이 들어와도 화면이 막아 주게 합니다.

## 18. 사용자 지적 수정 (2026-08-28)

### 18.1 홈 헤더의 국가 표시가 눌리지 않음

현재 `HomeScreen`의 국가 표시는 `<span className={styles.countryBadge}>{countryLabel} ▾</span>`입니다. **`▾`를 달아 눌릴 것처럼 보이는데 `button`이 아니고 핸들러도 없습니다.** 가짜 클릭 어포던스입니다.

`Chip` 컴포넌트가 `onClick`이 없으면 `button`이 아니라 `span`으로 렌더해 이 문제를 피하도록 설계돼 있는데, 헤더 배지는 그 원칙을 따르지 않았습니다.

**고치는 방향**: 실제로 국가를 바꿀 수 있게 만듭니다.

- `button`으로 바꾸고 누르면 국가 선택 시트를 엽니다.
- 시트는 `BottomSheet` 안에 `Chip`을 국가 수만큼 놓습니다. 선택된 국가만 `selected`입니다.
- 고르면 국가가 바뀌고 시트가 닫힙니다. '나' 화면의 국가 변경과 같은 상태를 씁니다.
- 국가를 바꾸면 열려 있던 상세는 닫습니다(7절 탭 이동 규칙과 같은 이유 — 이전 국가의 할 일이 유효하지 않습니다).

### 18.2 완료 취소 후 상세가 닫히지 않음

`undoDetail`이 완료만 취소하고 상세를 열어 둡니다. `completeDetail`은 처리 후 상세를 닫습니다. 두 버튼이 같은 자리에 있는데 한쪽만 화면을 벗어나 동작이 어긋납니다.

**고치는 방향**: `undoDetail`도 `completeDetail`처럼 상세를 닫고 이전 화면으로 돌아갑니다. 두 동작 모두 "이 항목에 대한 처리를 끝냈다"는 뜻이므로 결과가 같아야 합니다.

## 19. 사용자 지적 수정 2차 (2026-08-28)

### 19.1 우측 요약 패널이 전체 높이를 채우지 않음

데스크톱 1280×900에서 `aside`의 실측 높이가 556px입니다. 좌측 사이드바는 `100dvh`로 화면을 채우는데 우측만 내용 높이에 맞춰 잘립니다. 캔버스 목업은 좌우 패널이 같은 높이로 화면을 채웁니다.

우측 패널도 화면 높이를 채우고, 내용이 넘치면 패널 안에서 스크롤합니다. 하단에 `margin-top: auto`로 붙는 요소(홈의 어려움 카드)가 실제로 바닥에 붙으려면 이 높이가 전제입니다.

### 19.2 `+ 새 메모`가 등록과 모달을 동시에 실행

지금은 누르면 메모가 등록되면서 동시에 다른 모달이 뜹니다. **누르면 바로 등록만 되게 합니다.** 모달을 띄우지 않습니다.

우측 패널에는 이미 바로 적는 입력창이 있으므로, 거기 적고 `+ 새 메모`를 누르면 그 내용이 등록되고 입력창이 비워지는 흐름이면 충분합니다.

### 19.3 할 일 마감을 캘린더로 직접 고르기

지금은 `오늘까지 · 이번 주 · 이번 달 · 도착 후` 네 개의 고정 선택지뿐입니다. 이용자가 원하는 날짜를 직접 고를 수 있어야 합니다.

- 할 일 추가 시트의 마감 입력을 **날짜 선택**으로 바꿉니다. `TextField`의 `type="date"`를 그대로 씁니다(출국일 입력과 같은 방식, 10.1절).
- 기존 고정 선택지는 빠른 입력으로 남겨도 되지만, 날짜를 직접 고르는 경로가 반드시 있어야 합니다.
- 목록의 마감 표시는 카피 규칙(4절)대로 상대 표현을 유지합니다. 고른 날짜를 `오늘까지`·`3일 남음` 같은 형태로 환산해 보여줍니다.
- **오늘 날짜에 의존하므로 P-06과 같은 함정이 있습니다.** 환산은 반드시 클라이언트 effect 안에서 하고, `wabiLogic.ts`의 순수 함수로 빼 TZ 회귀 테스트를 붙입니다.

### 19.4 우측 패널에서 메모 삭제

우측 요약 패널의 메모 목록에서 바로 지울 수 있어야 합니다.

- 행에 마우스를 올리면 **휴지통 아이콘이 나타납니다.** 평소에는 보이지 않습니다.
- hover는 데스크톱 전용입니다(11.2절 확장 규칙). 터치 환경에서는 이 패널 자체가 없으므로 문제되지 않습니다.
- 삭제 전 확인을 받습니다. 문구는 16.10절 기준을 따릅니다.
- 아이콘만 있는 버튼이므로 `aria-label`을 반드시 답니다.

### 19.5 D-day 캡션과 숫자를 세로로

`호주 출국까지` 캡션과 `D-12`가 가로로 나란히 놓여 있습니다. 캔버스는 **세로**입니다 — 캡션이 위, 숫자가 아래이고 `flex-direction: column`에 `gap: 10px`입니다.

그 세로 블록이 진행률과 나란히 놓여 가로 행을 이룹니다(`align-items: flex-end`, `gap: 40px`). 즉 바깥은 가로, 안쪽 D-day 블록은 세로입니다. 이 중첩이 바뀌면 88px 숫자가 캡션에 밀려 위치가 어긋납니다.

### 19.6 기본 화면 모드를 다크로

앱의 기본값을 **다크 모드**로 바꿉니다 (사용자 지시 2026-08-28).

- `app/layout.tsx`의 `<html data-theme="light">`를 `dark`로 바꿉니다.
- 이용자가 '나' 화면에서 고른 값이 `localStorage`에 있으면 그것이 우선합니다. 인라인 스크립트의 동작은 그대로입니다(3절).
- 저장된 값이 없을 때만 다크가 기본입니다.

### 19.7 우측 패널을 하나로 통일 (사용자 지시 2026-08-28)

지금은 홈과 메모의 우측 336 패널이 서로 다릅니다. 홈은 `내 메모` + `+ 새 메모` + 빠른 입력 + 목록이고, 메모는 `WRITING` + 제목 입력 + 내용 입력 + `저장하기`/`삭제`입니다. **하나로 합칩니다.**

통일된 우측 패널의 구성입니다.

| 요소 | 내용 |
|---|---|
| 제목 | `내 메모` — `WRITING` 캡션은 없앱니다 |
| 입력 | **본문만.** 제목 입력칸을 제거합니다 |
| 등록 | `저장하기` 버튼 하나. **`+ 새 메모` 버튼은 없앱니다** |
| 목록 | 메모 목록. 행에 마우스를 올리면 휴지통(19.4절) |
| 홈 전용 | 하단(`margin-top: auto`)에 `먼저 간 사람들이 힘들어한 것` 카드 |

홈과 메모 화면이 같은 컴포넌트를 씁니다. 홈에만 하단 어려움 카드가 붙는 차이뿐입니다.

**메모 레코드에서 제목이 빠집니다.** 16.2절에서 캔버스 목업을 근거로 `title`을 추가했으나, 입력칸을 없애면 채울 방법이 없습니다.

- 목록의 제목 자리는 **본문 첫 줄**을 한 줄로 잘라 씁니다(제목 추가 이전의 방식으로 되돌립니다).
- 저장 레코드는 `{ id, body, updatedAt }`입니다. 이미 `title`이 들어간 레코드가 있을 수 있으므로 읽을 때 무시하고 깨지지 않게만 처리합니다.
- 캔버스 메모 목업은 제목과 내용을 나눠 두지만 **사용자 지시가 캔버스보다 우선합니다.**

### 19.8 '나' 화면의 정보 수정과 출국일 행

**정보 수정 버튼이 눌리지 않는 것처럼 보입니다.** 코드상 `button`이고 핸들러도 있지만, 하는 일이 설정 영역으로 스크롤하는 것뿐입니다. 데스크톱에서는 프로필 카드와 설정이 한 화면에 다 보여 스크롤할 곳이 없으므로 눌러도 아무 일이 일어나지 않습니다.

- 눌렀을 때 **눈에 보이는 반응**이 있어야 합니다. 설정의 출국일 입력에 포커스를 주는 편이 낫습니다. 스크롤이 필요한 구간에서는 스크롤도 함께 합니다.
- 그래도 데스크톱에서 할 일이 마땅치 않다면 이 버튼을 없애는 편이 낫습니다. **아무 일도 하지 않는 버튼을 두지 않습니다** — Chip이 `onClick` 없으면 `button`으로 렌더하지 않는 원칙과 같습니다.

**출국일은 행 전체를 눌러 설정합니다.** 지금은 값 텍스트 부분만 눌립니다.

- 행 전체가 클릭 대상이 되도록 `<label>`로 감싸거나, 날짜 입력을 행 전체 크기로 깔고 시각적으로만 감춥니다.
- 최소 48px 터치 영역을 유지합니다.
- 다른 설정 행(국가 변경 등)도 같은 방식으로 행 전체가 눌리게 통일합니다. 한 화면에서 어떤 행은 전체가 눌리고 어떤 행은 텍스트만 눌리면 어색합니다.

### 19.9 `+ 새 메모` 버튼 정리

`+ 새 메모` 버튼이 두 곳에 있었습니다. 우측 패널과 메모 화면 본문입니다.

- **우측 패널의 버튼은 없앱니다**(19.7절). 패널 자체가 적는 곳이므로 `저장하기` 하나면 충분합니다.
- **메모 화면 본문의 버튼**은 지금 누르면 편집 시트가 열립니다. 우측 패널이 있는 데스크톱에서는 적는 곳이 이미 화면에 있는데 그 위로 시트가 또 뜨는 셈이라 어색합니다.
  - 우측 패널이 있는 구간(데스크톱)에서는 **시트를 열지 말고 패널의 입력창에 포커스**를 줍니다.
  - 우측 패널이 없는 구간(모바일·태블릿)에서는 지금처럼 시트를 엽니다. 거기서는 시트가 유일한 입력 수단입니다.

### 19.10 사이드바 접기와 우측 패널 접기 (사용자 지시 2026-08-28)

**좌측 사이드바 접기 버튼이 동작하지 않습니다.** 캔버스 목업에 접기 아이콘이 그려져 있어 마크업은 있지만, 정적 목업이라 동작이 정의돼 있지 않다는 이유로 `span` + `aria-hidden`으로만 두었습니다. 보이는데 눌리지 않는 가짜 어포던스입니다(국가 배지와 같은 문제).

- `button`으로 만들고 누르면 좌측 사이드바가 **236 ↔ 88 아이콘 레일**로 접히고 펴집니다. 88 레일은 태블릿에서 이미 쓰는 형태이므로 새 시각 언어를 만들지 않습니다.
- 접힌 상태에서는 라벨이 사라지고 아이콘만 남습니다. 접기 버튼의 화살표 방향이 상태에 따라 바뀝니다.
- `aria-label`과 `aria-expanded`를 답니다.
- 선택 상태를 `localStorage`에 남겨 다시 방문해도 유지합니다.

**메모 탭에서는 우측 패널이 기본으로 접혀 있습니다.** 메모 화면은 본문이 이미 메모 목록과 입력을 담고 있어, 우측에 같은 기능이 또 있으면 중복입니다.

- 우측 패널에도 접기·펼치기 토글을 둡니다.
- **메모 탭은 기본이 접힌 상태**, 홈은 기본이 펼친 상태입니다.
- 접힌 상태는 얇은 띠와 펼치기 버튼만 남깁니다. 완전히 없애지 않는 이유는 이용자가 다시 펼 수 있어야 하기 때문입니다.
- 이 상태도 `localStorage`에 남깁니다. 다만 화면별로 따로 기억합니다 — 홈에서 접었다고 메모에서 펴지면 안 됩니다.

## 20. 사용자 지적 수정 3차 (2026-08-28)

### 20.1 메모 화면에서는 우측 패널을 쓰지 않습니다

19.10절에서 "메모 탭은 기본이 접힌 상태"로 했는데, 접기 토글이 남아 있어 펼 수 있습니다. **메모 화면에서는 우측 패널 자체를 쓰지 않습니다.**

- 메모 화면에서 우측 패널과 그 접기·펼치기 버튼을 **모두 없앱니다.** 접힌 띠도 남기지 않습니다.
- 본문이 이미 목록과 입력을 담고 있어 우측에 같은 기능이 있을 이유가 없습니다.
- 홈에서는 지금처럼 펼친 상태로 둡니다.

### 20.2 사이드바 접기 아이콘 교체와 애니메이션

- 지금 아이콘(세로 막대 + `‹`)이 거의 보이지 않습니다. **눈에 들어오는 다른 아이콘으로 바꿉니다.**
- 접히고 펴질 때 **부드러운 애니메이션**을 넣습니다. 폭이 236 ↔ 88로 뚝 끊기지 않게 합니다.
- 우측 패널도 화면을 옮길 때 **자연스럽게 닫히고 열립니다.** 메모로 들어가면 닫히고 다른 탭으로 나오면 열립니다.

### 20.3 모달 등장 애니메이션 통일

**아래에서 위로 올라오며 페이드 인**하는 방식으로 통일합니다. 지금은 구간마다 다릅니다.

- 모바일: 지금의 바텀 시트 그대로(이미 아래에서 올라옴).
- **태블릿 이상: 아래에서 위로 올라오는 슬라이드 + 페이드.** 11.4절의 "데스크톱은 위에서 8px 내려오며 페이드"를 대체합니다. 위치(모바일 전폭 하단 · 태블릿 620 하단 중앙 · 데스크톱 480 중앙)는 그대로 두고 **등장 방식만** 바꿉니다.
- **눌렀을 때 뜨는 모달은 전부 같은 방식**을 씁니다. 가이드, 국가 선택, 할 일 추가, 메모 편집, 할 일 상세를 포함해 예외를 두지 않습니다.
- 캔버스 11.4절의 데스크톱 등장 방식과 다르지만 **사용자 지시가 캔버스보다 우선합니다.**

### 20.4 '나' 탭을 '프로필'로

- 탭 라벨을 `나`에서 **`프로필`**로 바꿉니다. 좌측 사이드바·아이콘 레일·하단 탭바 모두 같은 라벨을 씁니다.
- 탭 id는 `me`를 그대로 둡니다. 저장된 상태와 어긋나지 않게 하기 위해서입니다.
- 캔버스는 `나`이지만 사용자 지시가 우선합니다.

### 20.5 프로필 카드 정리

- **`정보 수정` 버튼을 없앱니다.** 눌렀을 때 출국일 달력이 열리는 것이 이름과 맞지 않습니다.
- 대신 **프로필(아바타)을 누를 수 있게** 합니다. 프로필 사진을 바꾸는 자리입니다.
- **프로필 카드 안의 출처 링크(`SourceLink`)를 삭제합니다.**

### 20.6 프로필 사진 (사용자 지시 2026-08-28)

프로필(아바타)을 누르면 사진을 바꿀 수 있습니다. **저장은 `localStorage`입니다.** 16절에서 접은 파일 저장(IndexedDB·암호화·보관 기간)을 다시 들이지 않습니다.

**전제: 저장 전에 반드시 축소합니다.** 이것이 성립 조건입니다.

- 원본을 그대로 넣으면 안 됩니다. `localStorage`는 문자열 전용이라 base64로 약 33% 부풀고, 한도가 오리진당 5MB 안팎이며 테마·출국일·메모와 나눠 씁니다. 폰 카메라 사진(2~5MB)은 base64로 3~7MB가 되어 한도를 바로 넘기고, 동기 API라 쓰는 동안 화면이 멈춥니다.
- 처리 순서: 파일 선택 → `<img>`로 읽기 → `canvas`에 **정사각 크롭 + 256×256 축소** → `toDataURL("image/webp", 0.8)` → 그 data URL만 저장.
- 결과는 대체로 10~30KB이고 base64로도 40KB를 넘지 않습니다. **원본은 저장하지 않습니다.**
- 받는 형식은 `image/png`, `image/jpeg`, `image/webp`입니다. SVG는 받지 않습니다.
  - 저장하는 것이 원본이 아니라 캔버스로 다시 그린 래스터 결과이므로 16절의 매직 넘버 검증만큼 무겁게 갈 필요는 없습니다. `accept`와 `img.onerror` 처리로 충분합니다.
- 저장 실패(용량 초과 등)를 조용히 삼키지 않습니다. 실패하면 이용자에게 알리고 이전 아바타를 유지합니다.
- 사진이 없으면 지금처럼 국가 라벨 첫 글자를 씁니다. 사진을 지우는 수단도 함께 둡니다.

### 20.7 20절 반영 후 남은 세 가지 (PM 검증 2026-08-28)

**1. 메모 화면에서 우측 패널이 1px 남습니다.** `width: 0`으로 접어도 `border-left: 1px`이 그대로 남아 실측 폭이 1px입니다. 20.1절은 "접힌 띠도 남기지 않습니다"이므로 완전히 0이어야 합니다. 접힌 상태에서는 테두리도 함께 없앱니다.

**2. 프로필 화면의 제목이 아직 `나`입니다.** 탭 라벨은 `프로필`로 바뀌었는데 화면 `h1`은 `나`입니다. 한 화면 안에서 탭과 제목이 다르면 어색합니다. `h1`도 `프로필`로 맞춥니다.

**3. 홈 화면에 `h1`이 없습니다.** 나머지 세 화면은 각각 `할 일`·`메모`·`프로필`이라는 `h1`이 있는데 홈만 없습니다. 스크린리더로 훑을 때 홈만 제목이 잡히지 않고, 화면 제목으로 위치를 파악하는 흐름이 끊깁니다.

- 시각적으로 큰 제목을 새로 넣으라는 뜻이 아닙니다. 정보 예산(한 화면에 블록 3~4개)은 그대로 지킵니다.
- 이미 있는 브랜드 영역의 `Wabi`를 `h1`으로 올리거나, 화면 제목을 `h1`으로 두되 시각적으로만 감추는 방식(`sr-only`) 중에 택합니다.

### 20.8 사이드바 접기 버튼이 순간이동하듯 움직임 (PM 원인 규명 2026-08-28)

접고 펼 때 버튼이 부드럽게 움직이지 않고 튑니다. 실측한 좌표입니다.

```
접기 전  x=179 y=26
+60ms   x=87  y=63   ← y가 한 번에 37px 점프
+700ms  x=27  y=68
transition-property: transform
```

**원인**: 전환 대상이 `transform`뿐인데, 실제 위치 변화는 **레이아웃에서 나옵니다.** 사이드바가 236에서 88로 줄면 브랜드 줄이 재배치되고(라벨이 사라지며 버튼이 다음 줄로 밀림) 그 위치 변화는 애니메이션되지 않습니다. 레이아웃으로 움직이는 것은 전환할 수 없습니다.

**고치는 방향**: 버튼의 위치가 브랜드 줄의 재배치에 끌려다니지 않게 합니다.

- 버튼을 사이드바 기준으로 위치를 고정합니다(예: `position: absolute`로 상단 우측에 고정). 그러면 접힌 폭·펼친 폭에 따라 x만 바뀌고 y는 변하지 않습니다.
- 라벨(`Wabi`)은 사라질 때 폭이 줄거나 페이드되게 하되, 그 변화가 버튼을 밀지 않도록 합니다.
- 접힌 상태에서 브랜드 로고와 버튼이 겹치지 않게 배치를 확인합니다.

### 20.9 모달 애니메이션이 전부 동작하지 않음 (PM 원인 규명 2026-08-28)

**증상**: 사용자가 "아직 모달 등의 애니메이션이 없다"고 지적했습니다. 실측해 보니 가이드 모달을 연 지 120ms 뒤(0.22s 애니메이션의 중간)인데 `opacity: 1`, `transform: none`으로 이미 최종 상태였습니다.

**원인 — CSS Modules의 키프레임 스코프**입니다.

- `@keyframes`가 전부 `app/globals.css`에 **전역**으로 정의돼 있습니다(`wabiSheetUp`, `wabiFadeIn`, `wabiSlideIn`, `wabiModalRiseIn`).
- 참조는 전부 `.module.css` 안에 있습니다(`BottomSheet`, `GuideSheet`, `PainSheet`, `TaskDetailScreen`).
- **CSS Modules는 `.module.css` 안의 `animation-name`을 자동으로 스코프 처리합니다.** `wabiModalRiseIn`이 `BottomSheet-module__해시__wabiModalRiseIn`으로 바뀌는데 그 이름의 키프레임은 없습니다.
- 브라우저는 존재하지 않는 애니메이션 이름을 **오류 없이 무시**합니다. 그래서 지금까지 드러나지 않았습니다.

`wabiSheetUp`·`wabiFadeIn`·`wabiSlideIn`도 같은 구조이므로 **시트 애니메이션은 처음부터 한 번도 동작한 적이 없습니다.** 정적 스크린샷으로는 최종 상태만 보여 QA도 잡지 못했습니다.

**고치는 방향**은 둘 중 하나입니다.

1. 키프레임을 참조하는 `.module.css` 안으로 옮깁니다. 스코프가 맞아떨어집니다. 여러 모듈이 같은 키프레임을 쓰면 중복이 생깁니다.
2. 전역 정의를 유지하되 모듈에서 `animation-name: global(wabiSheetUp)`처럼 전역임을 명시합니다.

어느 쪽이든 **고친 뒤에는 반드시 실행 중에 측정해 확인합니다.** 애니메이션 중간 시점의 `opacity`나 `transform`이 최종값과 달라야 실제로 동작하는 것입니다.

### 20.10 사이드바 라벨이 즉시 사라짐

접기 버튼을 누르면 라벨이 부드럽게 사라지지 않고 즉시 없어집니다. 실측하니 60ms 시점에 이미 `display: none`이었습니다.

`transition: all`이 걸려 있지만 **`display`는 전환할 수 없는 속성**입니다. `display: none`은 단계 없이 즉시 적용됩니다.

`display` 대신 `opacity`와 `width`(또는 `max-width`)로 줄여 전환 대상이 되게 합니다. 접힌 뒤에도 자리를 차지하지 않아야 하므로 폭을 0으로 만드는 것이 함께 필요합니다.

### 20.11 사용자 지적 4차 (2026-08-28)

**1. 시트가 올라오는 속도가 너무 빠릅니다.** 할 일을 눌러 상세가 올라올 때 애니메이션이 눈에 남지 않습니다. 지속 시간을 늘립니다. 20.9절을 고쳐 애니메이션이 실제로 동작하게 된 뒤 체감으로 맞춥니다.

**2. 바깥 영역을 눌러도 닫힙니다.** 시트·모달이 열렸을 때 딤 영역을 클릭하거나 터치하면 닫힙니다. 닫기 버튼을 반드시 눌러야 하는 지금 방식은 번거롭습니다.
- `BottomSheet`에는 이미 딤 버튼이 있으므로 모든 시트가 같은 동작을 하는지 확인합니다. 할 일 상세처럼 시트가 아닌 전체 화면 오버레이도 포함합니다.
- 닫기 버튼은 그대로 둡니다. 키보드 사용자에게 필요합니다. `Escape`도 계속 동작해야 합니다.

**3. 날짜 입력은 칸 전체를 눌러 달력이 열립니다.** 지금은 오른쪽 달력 아이콘을 정확히 눌러야만 열립니다.
- 대상은 두 곳입니다. 할 일 추가 시트의 마감 입력과 '나'(프로필) 화면의 출국일 행입니다.
- **`<label>`로 감싸는 것만으로는 부족합니다.** 라벨 클릭은 입력에 포커스를 줄 뿐이고, 네이티브 날짜 입력은 포커스만으로 달력을 열지 않습니다. 그래서 출국일 행이 눌러도 아무 반응이 없습니다.
- 행이나 칸을 누르면 `input.showPicker()`를 호출합니다. 미지원 브라우저에서는 포커스로 대체합니다(정보 수정 버튼에 이미 쓰인 방식).

**4. 다크모드에서 달력 아이콘이 배경과 구분되지 않습니다.** 네이티브 날짜 입력의 아이콘은 브라우저가 그리는 것이라 CSS로 직접 색을 바꿀 수 없습니다.
- `color-scheme`을 선언합니다. `[data-theme="dark"]`에 `color-scheme: dark`, 라이트에 `color-scheme: light`를 둡니다.
- 이 한 줄로 날짜 입력 아이콘뿐 아니라 스크롤바·기본 폼 컨트롤이 모두 테마에 맞게 렌더됩니다. 현재 어디에도 선언돼 있지 않습니다.

### 20.12 사용자 지적 5차 (2026-08-28)

**1. 닫힐 때도 애니메이션이 필요합니다.** 할 일 상세가 올라올 때는 슬라이드가 보이는데 닫힐 때는 즉시 사라집니다. 열림과 닫힘이 어긋납니다.

- CSS 애니메이션은 요소가 붙을 때만 실행됩니다. 닫는 순간 바로 언마운트하면 나가는 애니메이션이 돌 틈이 없습니다.
- **닫는 중 상태를 두고, 나가는 애니메이션이 끝난 뒤에 언마운트합니다.** `animationend`를 기다리거나 지속 시간만큼 지연시킵니다.
- 시트·모달·상세 화면 모두 같은 방식으로 통일합니다. 들어올 때와 대칭인 방향으로 나갑니다(아래에서 올라왔으면 아래로 내려갑니다).
- 딤 배경도 함께 페이드 아웃합니다.

**2. 캘린더가 '출국일' 텍스트를 가립니다.** 원인은 날짜 입력의 위치입니다.

- 지금 `.dateInput`은 `width: 1px; height: 1px; clip: rect(0,0,0,0)`로 화면에서 감춰져 있습니다. 스크린리더용으로 감추는 흔한 방식입니다.
- 브라우저는 네이티브 달력 팝업을 **입력 요소의 위치에 붙여 엽니다.** 그 요소가 행 왼쪽 끝의 1×1 점이라 팝업이 행 위로 겹쳐 라벨을 덮습니다.
- **입력이 행 전체를 덮되 `opacity: 0`으로 보이지 않게 합니다.** 클립으로 1×1로 줄이지 않습니다. 그러면 팝업이 행 전체를 기준으로 잡혀 아래쪽으로 열립니다.
- 행의 라벨과 값은 입력 아래에 그대로 두고, 클릭은 `showPicker()`로 처리하는 지금 방식을 유지합니다.
- 같은 방식이 필요한 곳이 또 있는지 확인합니다. 할 일 추가 시트의 마감 입력도 같은 구조라면 함께 고칩니다.

### 20.13 사용자 지적 6차 (2026-08-28)

**1. 시트 안에서 스크롤이 되지 않습니다.** 모바일에서 '먼저 간 사람들이 힘들어한 것' 답변을 열고 스크롤하면 움직이지 않습니다.

- PM 재현: 390×420 뷰포트에서 `.body`의 `scrollHeight` 418 > `clientHeight` 256으로 **넘치는 것이 맞는데** 휠과 터치 모두 `scrollTop`이 0에서 변하지 않습니다.
- `.body`에 `overflow-y: auto`는 이미 있습니다. 포인터 이벤트가 스크롤 컨테이너에 닿지 않는 것이 원인으로 보입니다. 딤 버튼이 시트 위에 겹쳐 있거나, 조상 요소의 `touch-action`·`overflow` 설정이 스크롤을 막고 있을 수 있습니다.
- 고친 뒤 **실제 휠·터치 이벤트로 확인합니다.** `scrollTop`을 코드로 대입하는 방식은 포인터 처리를 우회해서 이 결함을 잡지 못합니다.

**2. 누르는 중·마우스를 올린 상태를 눈으로 알 수 있어야 합니다.** 지금은 어디를 누르고 있는지 표시가 없습니다.

- 대상: **메모 목록, 프로필 설정 행, 할 일 목록, 홈의 이번 주 할 일 목록** 전부입니다.
- hover는 데스크톱 전용(11.2절 확장 규칙), 누르는 중(`:active`)은 모든 구간에 적용합니다. 터치에는 hover가 없습니다.
- 새 색을 만들지 않습니다. `sunken`을 배경으로 쓰는 정도면 충분합니다.
- 키보드 사용자를 위해 `:focus-visible`도 같은 처리를 합니다.

**3. `+` 버튼이 너무 큽니다.** 모바일에서 할 일 탭과 메모 탭의 추가 버튼 크기를 **절반으로** 줄입니다. 최소 터치 영역 48×48px은 유지하고 아이콘만 줄입니다.

**4. 화면 모드 행을 눌러 전환합니다.** 프로필의 화면 모드가 테두리로 감싼 버튼과 화살표로 되어 있습니다.

- **테두리와 화살표를 지웁니다.**
- 행 어디를 누르거나 터치해도 라이트↔다크가 전환됩니다. 다른 설정 행과 같은 방식입니다(20.11절 3번).

**5. 프로필에 출처 링크가 남아 있습니다.** 20.5절에서 지웠다고 했으나 `MeScreen`의 모바일 정보 영역(비자 만료 줄 아래)에 아직 있습니다. 데스크톱 프로필 카드에서만 지워졌습니다. 이것도 지웁니다.

**6. 헤더 버튼에 누르는 느낌을 줍니다.** 헤더의 가이드 버튼과 국가 전환 버튼에 hover·active 시 살짝 축소됐다가 놓으면 돌아오는 애니메이션을 넣습니다.

- `transform: scale()`로 처리합니다. 레이아웃을 건드리지 않아 주변 요소를 밀지 않습니다.
- hover는 데스크톱 전용, active는 모든 구간입니다.
- 축소 폭은 크지 않게 둡니다. 눌린 느낌만 나면 됩니다.

**7. 모바일에서는 모든 탭에 헤더를 둡니다.** 지금은 홈에만 있습니다.

- 브랜드(`W` + `Wabi`)와 가이드 버튼, 국가 전환이 모든 탭에서 같은 자리에 보입니다.
- **로고를 누르면 홈으로 돌아옵니다.** 눌리는 요소이므로 `button`으로 만들고 `aria-label`을 답니다.
- 데스크톱은 지금처럼 헤더가 없습니다. 사이드바가 그 역할을 합니다(11.4절).

**8. 할 일 마감은 과거 날짜를 고를 수 없습니다.** 이미 지난 날짜를 마감으로 잡는 것은 의미가 없습니다.

- 날짜 입력에 `min`을 오늘로 둡니다.
- **P-06과 같은 함정이 있습니다.** 오늘 날짜에 의존하므로 `min` 값을 렌더 중에 계산하면 정적 프리렌더 시점(빌드 타임)의 날짜로 굳습니다. 하루만 지나도 어제 날짜가 `min`이 됩니다. **반드시 클라이언트 effect 안에서 계산해 넣습니다.**
- 출국일 입력에는 적용하지 않습니다. 이미 출국한 사람이 과거 날짜를 넣을 수 있어야 합니다.

### 20.14 사이드바 접힘 시 레이아웃 깨짐 (PM 재현 2026-08-28)

데스크톱에서 좌측 사이드바를 접으면(236 → 88) 배치가 깨집니다. 모바일·태블릿은 정상입니다.

**원인**: 라벨은 `opacity`·`max-width`로 사라지는데 **`할 일`의 미완료 개수 배지는 그대로 남습니다.** 88px 폭에서는 배지가 아이콘 옆에 들어갈 자리가 없어 아래로 밀리고, 그 탭만 세로로 한 줄을 더 차지해 네 아이콘의 간격이 어긋납니다.

- 접힌 상태에서는 **배지도 라벨과 함께 감춥니다.** 개수는 펼쳤을 때만 보여줍니다.
- 접힌 뒤 네 탭의 아이콘이 같은 간격으로 세로 정렬되는지 확인합니다.
- 88px 레일은 태블릿에서 이미 쓰는 형태입니다. 태블릿 레일과 같은 배치가 되는지 대조하면 어긋난 곳이 드러납니다.

### 20.15 화면 모드는 누르면 반대로 바뀝니다

20.13절 4번을 구체화합니다. 라이트·다크 중 하나를 **정확히 골라 누르는 방식이 아니라**, 행 어디를 누르든 **현재의 반대로 전환**됩니다.

- 두 개의 선택지를 나란히 두고 고르게 하지 않습니다. 값이 둘뿐이라 토글이 자연스럽습니다.
- 행 오른쪽에는 현재 상태(`다크` 또는 `라이트`)만 글자로 보여줍니다. 테두리와 화살표는 없습니다.
- `aria-pressed`나 `role="switch"`로 상태를 알립니다.
