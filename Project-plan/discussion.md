# Wabi 구현 계획서

## 0. 출처와 범위

- **원본**: `Docs/Design/WabiDesignSystem.dc.html` (Claude Design 프로젝트 `cc00ea2b-15f8-4984-a1f1-3739f99ec91b`에서 내려받은 사본)
- **디자인 명세**(색상·타이포·간격·컴포넌트·화면 구성·모션)는 원본 캔버스가 확정된 사실이므로 그대로 따릅니다. 임의로 바꾸지 않습니다.
- **제품 콘텐츠**(비자·세금·보험·계약 등 현실 정보)는 캔버스에 적혀 있더라도 확정된 사실이 아니라 화면을 채우기 위한 예시입니다. 직접 조사해 확인한 값으로 교체한 뒤에만 코드에 넣습니다. 조사는 Research-team에 의뢰했습니다.
- 원본은 디자인 시스템(01~04 섹션)과 **동작하는 프로토타입**(05 섹션)을 함께 담고 있습니다. 두 가지를 모두 구현합니다.

## 1. 제품 정의

워킹홀리데이를 준비하는 사람과 현지에 도착한 사람을 위한 모바일 우선 앱입니다. 할 일은 많지만 한 번에 알아야 할 것은 언제나 하나뿐이라는 전제로 설계되었습니다.

- 대상: 출국 전 준비 단계, 현지 정착 단계
- 첫 화면은 D-day
- 다국가 지원 (호주 / 캐나다 / 일본)
- 존댓말, 간결한 카피

## 2. 설계 원칙 (구현 시 반드시 지킬 것)

1. **한 화면에 블록 3~4개**. 그 이상 필요하면 다음 화면으로 넘깁니다. 목록은 3줄까지 보여주고 나머지는 '전체 보기'로 감춥니다.
2. **시선 순서를 고정합니다**. 위에서 아래로 상태 → 다음 행동 → 목록 → 탭바. 화면이 바뀌어도 이 순서는 바뀌지 않습니다.
3. **색이 아니라 크기로 강조합니다**. 팔레트는 무채색 하나뿐이고, 중요도는 타이포 크기·여백·잉크 대비로만 표현합니다. 유채색은 마감 임박 한 곳에만 쓰는 `alert` 하나로 제한합니다.

## 6. 데이터

데이터는 화면 코드와 분리해 `src/Front/common/data`(또는 Architecture가 정한 위치)에 둡니다.

### 6.1 구조 (캔버스에서 확정)

| 상수 | 구조 |
|---|---|
| `COUNTRIES` | 국가 코드별 `label / depart / visa` |
| `TASKS` | `id / phase(pre·post) / title / meta / week / urgent / tag / body / items / done` |
| `GUIDE` | 상황(`pre`·`post`)별 문항 배열, 각 문항은 `title / body / points` |
| `PAIN` | `num / when / title / body / points` |

분량 기준: `TASKS` 9건(pre 4 · post 5), `GUIDE` 상황별 5문항, `PAIN` 6건.

### 6.2 값 (조사 후 확정)

캔버스에 들어 있는 값 — 비자 심사 3주, 세금 번호가 없을 때 최고 세율, 계좌 개설 도착 후 3일 내, 보험 증서 요구 여부, 국가별 출국일과 비자 만료일 등 — 은 **확인되지 않은 예시**입니다. 다음 순서로 처리합니다.

1. Research-team에 국가별(호주·캐나다·일본) 실무 정보를 공식 출처 기준으로 의뢰합니다. 산출물은 `/home/fefdfea/FF/Organize/Research-team/Research-team/Result/Data/` 아래 JSON입니다.
2. 조사 결과가 도착하면 그 값으로 `TASKS` · `GUIDE` · `PAIN`을 다시 씁니다. 각 항목에는 출처 URL을 함께 보관합니다.
3. 조사로 확인되지 않은 항목은 임의로 채우지 않고 화면에서 뺍니다.
4. Front-end는 조사 결과가 오기 전까지 데이터 구조와 화면만 구현하고, 값은 조사 산출물로 주입받는 형태로 설계합니다.

`COUNTRIES`는 국가별로 다른 실제 요건을 담게 되므로, 세 국가가 같은 할 일 목록을 공유하던 캔버스 구조를 국가별 할 일 목록으로 확장해야 합니다.

## 7. 동작 명세

- 탭 이동 시 열려 있던 상세는 닫습니다.
- 체크 토글은 행 전체가 아니라 체크 원에서만 발생하며, 행 클릭은 상세를 엽니다 (이벤트 전파 차단).
- 완료 항목: 제목 `muted` + 취소선, 메타는 '완료'로 바뀝니다.
- 긴급 항목(`urgent`이고 미완료): 체크 테두리와 메타 글자가 `alert`.
- NEXT 카드는 미완료 항목 중 첫 번째를 보여주고, 설명은 본문의 첫 문장만 씁니다.
- 진행률은 기본 할 일 + 직접 추가한 할 일을 합쳐 계산합니다.
- 직접 추가한 할 일은 마감이 '오늘까지' 또는 '이번 주'이면 홈의 '이번 주 할 일'에 함께 나옵니다.
- 테마와 국가는 '나' 탭 설정에서 바꿀 수 있습니다.

## 8. 카피 규칙

1. 존댓말, 한 문장. 감탄사와 느낌표는 쓰지 않습니다.
2. 행동 버튼은 동사로 끝냅니다. "지금 하기", "가입하기", "예약하기".
3. 마감은 상대 표현으로. "오늘까지", "도착 후 3일 내".
4. 숫자는 단위와 붙여 씁니다. "8 / 14", "D-12".

- 마감 알림 규칙

## 10. 출국일 입력 (사용자 승인 2026-08-28)

D-day와 비자 만료일은 조사로 확인할 수 있는 사실이 아니라 이용자마다 다른 개인 값입니다. 캔버스가 `COUNTRIES`에 하드코딩해 둔 출국일과 비자 만료일은 쓰지 않고, 다음과 같이 입력받아 산출합니다.

### 10.1 입력 위치

'나' 화면의 설정 목록에 **출국일** 항목을 추가합니다. 기존 3개(화면 모드 · 알림 · 국가 변경)와 같은 60px 행 형식을 따르고, 값이 없으면 우측에 '입력하기'를, 있으면 선택한 날짜를 보여줍니다.

날짜 선택은 브라우저 기본 `input[type=date]`를 씁니다. 외부 의존성이 없고 모바일에서 OS 기본 날짜 선택기가 뜨며 키보드 접근성이 확보됩니다.

### 10.2 산출 규칙

- **D-day** = 출국일 − 오늘. 출국 당일은 `D-DAY`, 지난 뒤에는 `D+n`으로 표시합니다.
- **비자 만료일** = 출국일 + 국가별 체류 허용 기간(조사로 확인된 값). 해당 국가의 체류 허용 기간이 조사로 확인되지 않았다면 비자 만료일 줄을 표시하지 않습니다.
- 출국일이 입력되지 않았으면 홈의 D-day 자리와 '나' 화면의 출국일·비자 만료일 줄은 빈 상태 문구로 둡니다. 임의의 기본값을 넣지 않습니다.

### 10.3 구현 시 주의

- **오늘 날짜는 반드시 클라이언트에서 계산합니다.** 이 라우트는 정적 프리렌더 대상이므로 서버 렌더 시점에 `new Date()`를 쓰면 빌드 시점 날짜로 고정되고, 하이드레이션 불일치도 발생합니다.
- 출국일은 `localStorage`에 저장합니다. 저장 범위 경계는 Security 검토서 2절을 따릅니다.

## 11. 반응형 — 태블릿 · PC (캔버스 06절 기준으로 재작성 2026-08-28)

> **이 절은 전면 교체되었습니다.** 이전 명세(640/1024 브레이크포인트, 사이드바 240px, 본문 520/720px)는 제가 캔버스를 확인하지 않고 임의로 정한 값이었습니다. 디자인 캔버스에 06절 "태블릿 · PC"가 추가되어 있었고, 아래는 그 목업에서 그대로 옮긴 값입니다. 캔버스가 기준입니다.

### 11.1 브레이크포인트

| 구간 | 레이아웃 |
|---|---|
| `≤ 743px` 모바일 | 1열 + 하단 탭바. 기준 레이아웃 |
| `744 ~ 1179px` 태블릿 | 아이콘 레일 + 본문 620px 중앙 |
| `≥ 1180px` 데스크톱 | 사이드바 + 본문 + 우측 요약 |

### 11.2 확장 규칙 (캔버스 원문)

- **본문 폭은 620px에서 멈춥니다.** 넓어진 화면에서 글줄이 길어지지 않게 합니다.
  - 데스크톱에서 이 값을 확인할 때는 **컨테이너가 아니라 그 안의 실제 콘텐츠를 재야 합니다.** 홈·메모의 본문 컨테이너는 `flex: 1`이라 708px이고, 좌우 패딩 44px씩을 뺀 콘텐츠가 620px입니다. 컨테이너를 재면 620 초과로 오판합니다.
- **정보를 추가하지 않습니다.** 데스크톱 우측 요약은 다른 화면에 이미 있는 내용을 옮겨 놓은 것뿐입니다.
- **타이포만 한 단계 키웁니다.** D-day 60 → 88, 제목 24 → 30, 본문 15는 그대로 둡니다.
  - 두 값의 **적용 구간이 다릅니다**(QA가 캔버스 목업 대조로 확인). D-day는 모바일 60 · 태블릿 72 · 데스크톱 88로 **3단계**이고, 제목은 모바일 24 · **태블릿부터 30**으로 2단계입니다. 제목을 데스크톱에서만 키우면 태블릿이 캔버스와 어긋납니다.
- **터치와 커서를 함께 지원합니다.** 태블릿의 탭 대상은 모바일과 같은 최소 48px를 유지하고, hover 상태는 데스크톱에서만 씁니다.

> 한 줄 요약(캔버스): 모바일은 순서로, 데스크톱은 배치로 같은 우선순위를 만듭니다. 화면이 커져도 사용자가 먼저 보는 것은 언제나 D-day와 NEXT 하나입니다.

## 14. 이용자 파일 저장 (폐기 — 16절로 대체)

> **폐기됨 (2026-08-28)** — 파일 저장 기능 자체를 만들지 않기로 했습니다. 사유와 대체안은 16절을 보십시오.
> 아래 원칙은 나중에 파일 저장을 다시 논의할 때를 위해 남겨 둡니다.

이용자가 추가한 파일을 저장하게 된다면 **IndexedDB에 `Blob`으로** 저장하고 `localStorage`에는 넣지 않습니다. `localStorage`는 문자열만 담을 수 있어 base64로 부풀려야 하고 용량 한도가 5MB 안팎이며 동기 API라 큰 값을 다루는 동안 화면이 멈춥니다.

`localStorage`는 테마·국가·출국일·메모처럼 짧은 값에만 씁니다. 현재 저장 중인 값이 전부 여기에 해당합니다.

## 16. 문서 탭을 메모 탭으로 (사용자 지시 2026-08-28)

**이용자 파일 저장 기능은 만들지 않습니다.** 앞서 이 절에 있던 IndexedDB 저장·AES-GCM 암호화·파일별 키·60일 보관·매직 넘버 검사 명세는 전부 폐기합니다.

### 16.1 폐기 이유

파일 저장은 이 앱의 크기에 비해 딸려 오는 것이 너무 많았습니다. 암호화, 키 파쇄, 보관 기간 약속과 실제 삭제, 위장 파일 검사, 미리보기 샌드박스까지 붙었고 그중 어느 하나만 빠져도 이용자에게 한 약속이 깨지는 구조였습니다.

이용자 로컬 파일 경로를 참조하는 방식(File System Access API의 `showOpenFilePicker`)도 검토했으나 **Safari가 데스크톱·iOS 모두 미지원, Firefox 미지원, 표준 상태도 experimental**입니다(MDN browser-compat-data 직접 확인). 모바일 우선인 이 앱에서 iOS 이용자가 기능을 아예 못 쓰게 되므로 채택할 수 없습니다.

서류 정보 자체는 이미 할 일 상세의 "준비물"이 전달하고 있어 정보 전달 목적에는 구멍이 없습니다.

### 16.2 대신 넣는 것: 메모

문서 탭 자리에 **이용자가 직접 적는 메모**를 둡니다. 남이 만든 파일을 보관하는 것이 아니라 이용자가 스스로 적어 두는 것이라, 앞의 무거운 장치들이 필요 없습니다.

- 탭 라벨을 `문서`에서 `메모`로 바꿉니다. `TabBar`의 아이콘과 위치, 4탭 구성은 그대로입니다.
- 메모 한 편은 **제목과 본문**입니다. 캔버스 데스크톱 메모 목업이 제목 입력과 내용 입력을 나눠 두고 있고, 목록도 제목 + 부제(내용 요약) + 날짜로 그립니다. (이전 명세는 본문 하나였으나 캔버스 확인 후 정정)
- 저장은 `localStorage`입니다. 테마·출국일·직접 추가한 할 일과 같은 자리에 둡니다. 짧은 텍스트라 IndexedDB가 필요 없습니다.
- 레코드: `{ id, title, body, updatedAt }`.

### 16.3 화면

- **목록**: 제목 + 내용 한 줄 요약 + 날짜입니다. 최근 수정 순으로 정렬합니다.
- **추가·편집**: `BottomSheet` 안에서 합니다. 여러 줄을 입력해야 하므로 **`TextArea` 컴포넌트를 `common/component`에 새로 만듭니다.** `TextField`의 규격(radius 14, `sunken` 배경, 1.5px `line` 테두리, 15px)을 그대로 따르되 높이만 늘리고 세로 리사이즈를 막습니다.
- **삭제**: 목록 행에서 삭제할 수 있게 하고 확인을 한 번 받습니다.
- **빈 상태**: `아직 적어 둔 메모가 없습니다.`

### 16.4 카피

파일 저장 시절의 문구는 전부 걷어냅니다. "기기에만 저장", "60일 후 자동 삭제", "만료일 알림" 같은 표현이 남아 있으면 안 됩니다.

- 화면 안내 한 줄: `기억해 둘 것을 적어 두세요. 이 기기에만 저장됩니다.`
- **추가·편집 시트 안내 한 줄** (`SecurityReview.md` 9절 권고): `계좌번호나 여권번호처럼 민감한 정보는 적지 않기를 권합니다.`

메모는 평문으로 저장합니다. 로그인도 앱 잠금도 없는 구조에서는 암호화를 넣어도 실질적인 보호가 되지 않기 때문입니다(파일 저장에서 확인한 것과 같은 이유). 이용자가 무엇을 적을지 통제할 수 없으므로 막는 대신 알려주는 쪽을 택합니다. 앱 잠금 기능이 생기면 그때 재검토합니다.

`localStorage`도 브라우저 저장공간을 지우면 사라지므로 영구 보존을 암시하지 않습니다. 다만 이용자가 직접 적은 짧은 글이라 파일 때처럼 강한 경고는 두지 않습니다.

## 17. `SourceLink` 스킴 검사 (`SecurityReview.md` 9절)

`SourceLink`가 URL 스킴을 검사하지 않아 `https` 전용 규칙이 데이터 규율에만 의존하고 있습니다. 조사 결과에 `http` URL이 섞이면 그대로 렌더됩니다.

`new URL(url).protocol`이 `"https:"`가 아니면 **아무것도 렌더하지 않습니다.** 파싱 실패 시 `null`을 반환하는 기존 처리와 같은 방식입니다. 데이터에 잘못된 값이 들어와도 화면이 막아 주게 합니다.

## 18. 사용자 지적 수정 (2026-08-28)

### 18.1 홈 헤더의 국가 표시가 눌리지 않음

현재 `HomeScreen`의 국가 표시는 `<span className={styles.countryBadge}>{countryLabel} ▾</span>`입니다. **`▾`를 달아 눌릴 것처럼 보이는데 `button`이 아니고 핸들러도 없습니다.** 가짜 클릭 어포던스입니다.

`Chip` 컴포넌트가 `onClick`이 없으면 `button`이 아니라 `span`으로 렌더해 이 문제를 피하도록 설계돼 있는데, 헤더 배지는 그 원칙을 따르지 않았습니다.

**고치는 방향**: 실제로 국가를 바꿀 수 있게 만듭니다.

- `button`으로 바꾸고 누르면 국가 선택 시트를 엽니다.
- 시트는 `BottomSheet` 안에 `Chip`을 국가 수만큼 놓습니다. 선택된 국가만 `selected`입니다.
- 고르면 국가가 바뀌고 시트가 닫힙니다. '나' 화면의 국가 변경과 같은 상태를 씁니다.
- 국가를 바꾸면 열려 있던 상세는 닫습니다(7절 탭 이동 규칙과 같은 이유 — 이전 국가의 할 일이 유효하지 않습니다).

### 18.2 완료 취소 후 상세가 닫히지 않음

`undoDetail`이 완료만 취소하고 상세를 열어 둡니다. `completeDetail`은 처리 후 상세를 닫습니다. 두 버튼이 같은 자리에 있는데 한쪽만 화면을 벗어나 동작이 어긋납니다.

**고치는 방향**: `undoDetail`도 `completeDetail`처럼 상세를 닫고 이전 화면으로 돌아갑니다. 두 동작 모두 "이 항목에 대한 처리를 끝냈다"는 뜻이므로 결과가 같아야 합니다.
